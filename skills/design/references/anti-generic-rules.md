# Rules against generic AI-looking UI

Generated interfaces tend to drift toward the same defaults. Check every direction and every finished screen against this list. A banned default is allowed only when the design persona or the brand gives a specific reason, which must be written in the style guide.

## Banned defaults

- Purple-to-blue or pink-to-orange gradients, especially on hero sections and buttons.
- One sans-serif typeface (Inter, Roboto, or the system font) for everything, with no contrast in type.
- A centred hero with a headline, a subline, two buttons, and three feature cards with icons below it.
- Emoji used as icons or as bullet points.
- Glassmorphism (frosted translucent panels) and soft neon glows.
- Every element in a rounded card with the same large radius and a soft drop shadow.
- Generic 3D blobs, abstract gradient meshes, or stock illustrations of people at laptops.
- Lorem ipsum, "John Doe", "Feature 1", or any other placeholder copy.
- Buttons labelled "Get started" or "Learn more" when a specific verb would work, such as "Swap a plant" or "Book a slot".
- A grey background with white cards as the only layout idea.
- Default chart colours, or decorative charts with no real data.

## Required in every direction

- **A deliberate type pairing.** Two typefaces with a clear job each (for example a display face for headings and a text face for the body), or one family used with strong contrast in size and weight. Name the fonts and say why they fit the persona.
- **A palette from the brand mood.** 5 to 7 colours, each with a stated role (background, surface, text, muted text, accent, status). The accent is used sparingly.
- **One signature element.** Something a user would recognise the app by, such as a shape, a texture, an illustration style, a layout device, or a motion pattern. It is used consistently, not everywhere.
- **Real copy** in the brand voice, including microcopy: buttons, empty states, and errors.
- **Real-looking data** with believable names, numbers, and dates that fit the user persona.
- **A layout idea,** stated in one line, for example "a single scrolling column with a sticky action bar" or "a split view with a persistent map".

## Final check on each screen

Answer each question honestly. Any "yes" means the screen needs another pass:

1. Could this screen belong to any other app if the logo were swapped?
2. Does any part look like a template a generator would produce by default?
3. Is there anything on the screen that the design persona would refuse?
4. Is the accent colour doing more than one job, or used in more than about 10% of the screen?
5. Is any text a placeholder, or vaguer than it needs to be?
